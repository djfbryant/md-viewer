Deepen the Document lifecycle

src/App.tsx:96–118, 157–183 · src/lib/instant.ts · instant.schema.ts · instant.perms.ts · src/AppDocument.test.tsx:4–29

Problem

The current database module is shallow: Editor, Reader, and tests must learn transaction shape, query shape, permission parameters, timestamps, and failure meaning.

Solution

Concentrate publication, reading, capability enforcement, and lifecycle outcome translation in one deep Document lifecycle module; keep InstantDB behind the true external seam.

Benefits

  • • locality: permission bugs concentrate
  • • leverage: future flows reuse rules
  • • tests hit one interface
  • • mock adapter replaces DSL imitation
Deletion test: deleting src/lib/instant.ts only moves two lines; deleting the deep module would spread lifecycle rules across Edit Links, images, expiry, deletion, Editor, and Reader.

Deepen Markdown interpretation

src/document.ts:3–5 · src/App.tsx:107, 147, 150, 166–167 · src/styles/app.css:59–66 · src/document.test.ts

Problem

Understanding one Document requires bouncing between a shallow helper, two render call sites, inline metadata, styling, and end-to-end tests.

Solution

Concentrate safe rendering policy, title and metadata derivation, shared Reader presentation, and source behaviour in one deep in-process module.

  • • interface becomes test surface
  • • parser changes stay internal

Problem

Editor behaviour is distributed across state, refs, direct DOM writes, CSS selectors, and publishing callbacks; the tests inspect text instead of interaction outcomes.

Solution

Concentrate authoring-session transitions, recovery, saved-versus-draft meaning, workspace invariants, and cleanup in one deep module with browser details internal.

  • • leverage across event handlers
  • • tests observe full sessions
  • • CSS checks shrink

Deepen Share Link routing

src/document.ts:1, 7–23 · src/App.tsx:181–183, 188, 203–225 · src/document.test.ts · future Edit Links and public pages

Problem

Callers must know path grammar, encoding, history updates, routing precedence, and capability meaning; currently every unknown non-share path opens the Editor.

Solution

Concentrate route recognition, capability interpretation, URL construction, unavailable outcomes, and browser-history behaviour in one deep navigation module.

Benefits

  • • locality: capability meaning concentrates
  • • leverage for Edit Links
  • • route table becomes test surface
  • • malformed paths stay internal
Deletion test: existing helpers retain encoding complexity but leave orchestration outside; deleting the deeper module would spread precedence and capability rules across Home, Editor, Reader, and future public destinations.
